# Common-tool tidy corpus

A curated corpus of **common Linux tool outputs** plus a batch harness, used to
drive glean toward its design goal: turn any tool output into tidy data with a
**minimum of strategies** — ideally only the generic format parsers plus
declarative hint rows, no per-tool parser code.

- `inputs/<tool>.txt` — a representative captured output for each tool. These are
  the regression inputs; keep them stable.
- `expected.tsv` — the correctness manifest: for each input, the expected tidy
  shape (`table` = strict data-row count, `kv` = key/value snapshot; plus a
  minimum column count).
- `expected/<tool>.tsv` — frozen golden tidy output, written **only** for tools
  that currently come out correctly tidy (so the golden gate tracks the covered
  set exactly).
- `run.sh` — the batch harness (one script, all inputs).

## Running

```bash
bash tests/corpus/run.sh                 # report: full vs --generic winner, tidy? per tool
bash tests/corpus/run.sh --coverage      # markdown coverage table (regenerates COVERAGE.md)
bash tests/corpus/run.sh --golden        # regression: diff generic tidy output vs goldens
bash tests/corpus/run.sh --update-golden # re-freeze goldens for the covered tools
```

**Which tools are covered?** See [`COVERAGE.md`](COVERAGE.md) (generated by
`run.sh --coverage`) for the live ✅/⏳ list.

`run.sh` runs each input through the extract engine in **`--generic`** mode (only
the fundamental parsers) — and, for the report/coverage views, **full** mode too
— then melts the result and checks it against the manifest. The `--generic`
column is the one that matters: it measures how well glean tidies each tool
*without a bespoke strategy*.

**Speed:** inputs are processed in parallel (a job pool sized to the CPU count,
override with `GLEAN_CORPUS_JOBS=N`), and each engine call uses `--emit-meta` so
the wide output and the winning-strategy meta come from one invocation; full mode
is skipped in `--golden`/`--update-golden`. On a 4-core box: report/coverage
~18s, `--golden` ~2.5s (was ~2 min).

## Tested tools & current coverage

**3706 tools tested; 3546 tidy (160 format gaps ⏳)** — after two +500
expansions of unique never-before-seen tools (461/500 and 466/500 of which
tidied with no new per-tool code — ~92% generalization each time), a gap-closing
round that fixed 41 of the 67 ⏳ with format-level capabilities only, a +99
benchmark-tool set (a new markdown pipe-table parser), and a full-range fio
expansion (12 output modes — all handled — via a headerless-numeric-CSV fix plus
two new generic parsers, `semicolon-values` and `labeled-inline-kv`). Of the
total: ✅ 3314 by a generic parser via auto-detection, ✅ʰ 83 by a generic parser
routed by a hint row, ✅ᵇ 149 by a bespoke strategy. (The count dropped from a
looser 3571 when a 2026-07-13 manifest-discipline pass made the harness honor
each `text`-kind entry's recorded min-column count instead of a hardcoded ≥2,
so ~28 lossy parses that had been passing on shape alone are now honest ⏳.) A later positional
multi-word-header round in `aligned-columns` closed most of the fixed-width
tables (stream/blender/pytest + frr/gluster/watch-diff/nodetool). A later
multi-mode coverage audit across all ~1000 tools confirmed the corpus already
samples many modes per high-fanout tool (kubectl 54, aws 46, git 43, docker 28,
ip 20, …) and added 3 net-new generic-tidy mode samples (pvesm-status, rbd-du,
zk-mntr). A segment-split round (`_ac_split` in `aligned-columns`, HDR-only)
then closed right-aligned space-in-value fixed-width tables — `ceph osd df`'s
"1.0 TiB" under a "RAW USE" multi-word header — and improved 8 already-covered
tables (multi-word headers joined, space-in-value cells preserved). A third
+539 expansion (batch 3: cloud/k8s/db/observability/networking/security/build/
ML/hardware/storage CLIs) tidied **529 of 539 (98%) with no new per-tool code**.
Finally, a +500 **adversarial** round — inputs generated specifically to BREAK
the parser across 10 hard mechanisms — found the parser robust to embedded ANSI
color, grouped 2-row headers, paragraph-stanza records and TUI/progress bars,
and rebuilt `box-table` (heavy/double/tabulate/dotted glyphs, interior-only
rows, csvlook dash rule) to close 8 box-drawing breakers; 431 of the 500 tidy in
full mode. A follow-up tree-flattening round then raised `tree-view`'s priority
above the generic record parsers (so glyph hierarchies stop collapsing to a
single record) and taught it more indent/marker conventions — closing most of
the deep-tree cluster (pnpm/ip-netns/conda/systemd-cgls/npm/yarn/…) and cleaning
connector debris from gradle/ansible names. Single-resource multi-line records
(`kubectl describe`, `systemctl status`) were then recognised as the key/value
snapshots they are — reclassified `table`->`kv` (8 fixtures) rather than forced
into a bogus table. Most recently, an **engine-level ANSI strip** removes VT
colour escapes once per input (gated on an ESC byte, a no-op otherwise) — fixing
colored tools (`gh`, `terraform plan`) and cleaning raw `\e[..m` codes out of 45
already-covered `*-color` goldens — and `box-table` gained interior-row and
duckdb "type row" handling (closing supabase / psql-unicode / duckdb box
tables). A short manifest-audit pass then reclassified three fixtures that were
already tidying correctly but mis-scored: `kubectl-get-svc-none` and
`lsblk-empty-mountpoint` were genuinely tidy tables (`<none>` / empty-mountpoint
cells preserved) miscounted by one data row, and `systemctl-status-nginx` is a
single-unit status snapshot — a key/value record, like the other eight
describe/status fixtures — not a table. A gap-triage pass then routed
`vercel-list` (a banner + fixed-width deployment table that `indented-hierarchy`
was collapsing) to `aligned-columns` via a structural hint row (`Age +Deployment
+Status`), and confirmed the rest of the tractable-looking candidates are not
clean wins: banner-table siblings (`pueue-status`, `apachectl-S`) are stolen by
`indented-hierarchy` at detection and their banners aren't stripped;
`lsblk-tree` can't be hinted without demoting its already-generic siblings;
`df-locale-de` is a UTF-8/mawk byte-position problem (umlaut columns); and the
wide-stat cluster (`sar-cpu`, `numastat-p`, `quota-report`) has embedded
time/grouped/`|`-separated headers. A second **+510 adversarial** round then
generated inputs specifically to BREAK the parser across novel mechanisms
(encoding/whitespace pathologies, Unicode display-width vs byte math, numeric
punctuation, embedded-delimiter quoting, structural table oddities, nested
multi-section records, stacked color+box+emoji, and real-tool exotics like
`openssl x509`, `ss -i`, `smartctl -a`). **393 of the 510 tidied with no new
per-tool code (77%)** — a deliberately low rate, since these were built to fail —
and the break-hunt surfaced one clean format-level fix: an **engine-level
line-terminator normalization** (once, gated) that maps Windows CRLF, bare-CR
(classic Mac), vertical-tab / form-feed page breaks, and the Unicode line
separators NEL / U+2028 / U+2029 to `\n`, so a capture using any of them no
longer collapses to a single physical line. A follow-up **`ini-sections`** generic
parser then closed the multi-section INI/config cluster: `[section]` + `key =
value` dumps that `equals` was flattening into one wide record (colliding
duplicate keys across sections) now tidy to lossless (section, key, value) rows —
closing `nst-ini-duplicate-keys` / `-php-ini-sections` / `-tox-ini-sections` and
improving 9 already-covered configs (gitconfig, `systemctl cat`, rclone/gcloud
config, …) from a duplicate-column form to the clean section table. It fires only
on distinct simple-token sections, so ffprobe `[STREAM]` blocks, spaced section
names and real TOML are left to their own parsers. The `csv` parser then became
**RFC-4180 quote-aware end-to-end**: detection now counts only commas *outside*
quoted fields (quoted CSV used to fail the consistency check and fall through to
a worse parser), the header is split with the same quote-aware splitter (a
`"Last, First"` header column no longer misaligns every row), the multi-line
joiner keys on an *open quoted field* instead of raw quote parity (so a literal
inch-mark `3/4"` row is no longer welded into the next line), and quotes are
structural only at field start with `""` as the escape — closing
`quo-csv-currency-thousands` / `-tags-column` / `-inch-marks` and improving 12
already-covered quoted-CSV fixtures (misaligned/garbled parses → correct
columns; escaped quotes preserved as data). A new **`quoted-fields`** generic
parser then closed the access-log family: space-delimited positional records
where `"…"`, `'…'` and `[…]` group a multi-word value into one field (apache
combined / nginx access logs, quoted app logs, quoted crontabs). Grouping is
structural only at token start, so logfmt (`msg="…"`) and quoted CSV never
match; detection demands a quote span on EVERY line, ≥5 fields, a near-constant
field count, and declines DNS RRs (`IN TXT`) — leaving dig, bracket-tag logs and
JSON to their own parsers (verified by a full-corpus firing-surface scan: 5 gaps
closed + exactly 3 flips, all improvements — `lspci-mm` one-blob → 7 columns,
`nginx-access-log-quoted` garbled → clean 9-column table, `quo-haproxy-log-quoted`
no longer splits its quoted request). A **table-chrome** round then taught
`aligned-columns` (and the `columnar-specs` engine) to drop rows that are table
furniture, not data: mid-table HEADER REPEATS (watch/top/vmstat/ps re-print the
header every page/interval — dropped only when token-identical to a digit-free,
≥3-token header, so a legitimately repeated log line survives) and a UNITS ROW
directly under the header (`(C) (RPM) (V)`, `MHz dBm dB` — recognised only in
that position, digit-free, deeper-indented, all tokens short and unit-shaped, so
an all-lowercase data row with an empty first cell is never eaten). Four
totals-footer fixtures were aligned with the corpus-wide convention that a
`TOTAL`/`Average:` row IS a data row (the ✅ sar family, `rsync-stats` and
`coverage-report` goldens all keep theirs). Closed 10 ⏳ and cleaned the repeated
header out of 4 already-covered goldens (faillock, iostat-x, curl's second
header-fragment row). An **engine-level Unicode-space normalization** (once,
gated — the same pattern as the ANSI strip and line-terminator fixes) then maps
NBSP, narrow-NBSP, the U+2000–U+200A quad/en/em/thin/hair family, medium math
space and the CJK ideographic space to ASCII space, so column splitting sees the
alignment the terminal showed; a single normalized NBSP inside a locale-grouped
number ("1 234,56") survives the 2+-space column rule, so grouping and padding
coexist. And `aligned-columns` header detection now accepts **non-ASCII label
tokens** — a CJK header row (`名前  年齢  都市`) had no `[A-Za-z0-9]` so it was
never promoted; those tables now get real column names. Together: 7 more ⏳
closed (NBSP/em/thin/ideographic padding, hangul/JP tables, formfeed pages).
Then **`semicolon-values` got the csv treatment**: top-level (quote-aware)
semicolon counting and splitting with `""` escapes, plus a low-density band —
2-3 separators accepted only when EVERY line has the IDENTICAL top-level count
(prose with stray semicolons varies and never qualifies; fio's dense ±1 band is
untouched). Closed 5 ⏳ (European-locale `;`-CSV with embedded `; ` in quoted
cells, decimal commas, NBSP thousands) and improved 4 already-covered fixtures
that had been parsed as blobs by text-lines/line-records — now real headers and
columns with `"paid; net 30"` kept whole. A **wrapped-cells** round then taught
the positional path in `aligned-columns` to rejoin continuation lines: a grid
row whose only content sits in the LAST cell (first cell empty) is the previous
row's last column wrapped onto a new line (kubectl events' MESSAGE, systemctl's
DESCRIPTION, crontab COMMAND) and is appended, space-joined. The same round
uncovered — and fixed — a long-standing positional bug: `IFS=$'\t' read -ra`
treats TAB as IFS whitespace, so EMPTY grid cells collapsed and every value to
their right shifted one column left; a tab-safe splitter now keeps cells in
place, correcting the empty-cell column labeling of 22 already-covered tables
(docker/podman ps with empty PORTS, lastlog's Never-logged-in rows, sparse
network/volume listings). Closed 4 wrapped ⏳; `tbl-df-wrapped-device` stays
open (first-column overflow in a single-space numeric table — the fixed-width
byte-offset family). A **`grouped-rows`** generic parser (priority 41 — after
block-records/tree-view, before indented-hierarchy) then opened the
nested-records frontier: an outer GROUP line (`Region: us-east-1`,
`COMMAND=nginx PID=1201`, `Node node-01:`, a bare `Images`, or
`Filesystem UUID: … Label: …`) over INDENTED tabular rows, through two levels,
with each group's keys carried down onto its leaf rows — the lossless tidy for
per-record sub-tables, grouped subtotals and namespace→resource listings.
Detection demands the leaf rows BE a table (modal token count ±1 over ≥70% of
rows, leaves ≥ groups, no YAML list markers), so ifconfig-style attribute
blocks, kv hierarchies and YAML never match; four kv-flavoured outputs the
first cut token-souped (volta, vulkaninfo, numpy-config, lsusb -v) are pinned
to their original parsers by hint rows. Closed 11 nested ⏳, promoted two
bespoke-tier inputs to generic (`iotop`, `proc-devices` — their per-tool
strategies are no longer their only route), and improved `pulumi-preview` and
`yugabyte-cluster-status` (the carried group column is the point: Masters vs
TServers rows are finally distinguishable). A **`pivot-stats`** parser then took
the last piece of that frontier — the `ip -s link` PIVOT shape, where a label
line (`RX: bytes packets errors …`) is the column header of the single value
row that FOLLOWS it. One wide row per record: the interface name, generic
`word value` pairs from its header line (mtu, qdisc, state, …), and each pivot
folded into prefixed counters (rx_bytes, tx_packets, …). Routed by one hint row
(`RX: +bytes` → pivot-stats) so it also beats the early key-value parser on
`ip -s addr`; closes the whole 4-fixture family plus `exo-ip-s-s-link` (whose
old golden was welded blobs; the doubled `RX errors:` sub-counters remain the
residual). A manual review of `review-output/` then caught two false-positive
detection bugs: `aligned-columns` was claiming single-record colon-kv
description blocks (`apt-cache show`, `dpkg -s`) before `colons` could, turning
row 1's two tokens into literal column names — it now declines when a block is
majority-distinct `Label:` lines AND row 1 itself is one (real tables whose
first *column* is colon-suffixed labels, like `/proc/interrupts`, keep their
row-1 real header and are unaffected). And `csv` was false-detecting on
bracketed thousands-grouping commas (`apt-get`'s `[1,234 kB]`) that gave a
spuriously consistent per-line comma count; a precise thousands-comma exclusion
(digit before, exactly 3 digits after, no 4th) fixes it while preserving the
comma-count *variation* `vegeta-report` needs to correctly decline csv. Fixed 7
kv-header targets + apt-get-download-progress + vegeta-report, incidentally
un-broke 8 pre-existing csv false positives, and closed `perf-stat-scientific`.
The 135 ⏳ that remain are
genuinely hard (nested multi-record blocks — `ip -s link`'s RX:/TX: sub-tables; headerless
first column — kdiskmark; single-space multi-word cells — lzbench; Unicode-space
column separators — NBSP/ideographic-space; quote-aware CSV/pipe splitting;
prose/diff formats — cargo clippy, git diff; nested/2-line-header records). See
[`COVERAGE.md`](COVERAGE.md) for the live per-tool list.

Coverage tiers, in order of preference:

1. **Generic (✅)** — one of the ~28 format-level parsers in
   `extract/strategies/delimited/` and `extract/strategies/structured/` (led by
   `aligned-columns`, `line-records`, `psql-table`, `colons`, `text-lines`,
   `key-value`, `indented-hierarchy`, `yaml`, …) detects and tidies the output
   with no per-tool knowledge at all. This is the tier that generalizes to
   unseen tools.
2. **Hint row (✅ʰ)** — the format is parseable by a generic strategy but
   auto-detection picks the wrong one, so one TAB-separated data row in
   `extract/hints.tsv` (tool, signature, target strategy) routes it. A hint is
   per-tool *data*, not per-tool *code*: signatures are structural (format
   shape), so they also match unseen output of the same tool.
3. **Bespoke (✅ᵇ)** — a per-tool strategy script, kept only where the format
   is genuinely idiosyncratic (sysstat banners, DNS answer sections, storage
   trees, `/proc` stat tables, grouped network stats, …) or where the generic
   parse is shape-tidy but qualitatively worse (`free`, `lvdisplay`,
   `mysqladmin-status` — verified by the golden-quality audit). Every bespoke
   strategy that survived is the proven full-mode winner for at least one
   corpus input; everything else was deleted.

There is also a **held-out generalization set** — [`holdout/`](holdout/): a
second, *different* output per tool (other hosts, versions, values, flags)
with no goldens, judged on tidy shape only, the way an unseen capture would
be. `bash tests/corpus/holdout/run.sh` runs it and attributes each win to a
tier; new entries should land generic/hint, not bespoke. This is the measure
of generalization (the main corpus, with its frozen fixtures, only measures
regression).

New tools added to the corpus should be checked against the generic parsers
first (`run.sh`); then try a hint row; reach for a bespoke strategy only when
no generic strategy produces a correct tidy shape even when forced
(`envoy-extract --strategy <name>`).

The design principle holds: the bulk of common tool output collapses onto a
handful of structural parsers, not one rule per tool. The corpus includes varied
output for the same tool (`free`/`free -h`, `df -h`/`df -i`, `ps aux`/`ps -ef`).

The corpus makes coverage measurable and regression-proof: `run.sh --golden`
diffs each tool's tidy output against a frozen golden, and the full extract
suite (`extract/tests/run_tests.sh`) is kept green through every parser change.
